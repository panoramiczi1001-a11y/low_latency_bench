# 原始输出：x86-64 / Intel Core Ultra X9 388H

**环境**：Linux 虚拟机，2 vCPU，g++ 15（`-O2 -std=c++20`）。
单核实验用 `taskset -c 0` 绑核；`exp6` / `exp7` 涉及跨核，不绑核。
采集时间 2026-11-11。

> 虚拟机，不是裸机。绝对值比真机偏慢，但**趋势与比例**可靠。

## 汇总

| 实验 | 关键数字 | 备注 |
|---|---|---|
| `cache_probe` | 步长 32 B→64 B 时 1.9→2.9 ns/hop；工作集 ≥16 MiB 跳到 96–135 ns | cache line = 64 B；L1 ≈32 KiB，L2 ≈1–2 MiB，L3 ≈8–16 MiB，内存 ≈130 ns |
| `exp1` 线性追逐 | 3.96 ns/hop（8 MiB） | 预取器有效工作 |
| `exp2` 随机追逐 | 145.14 ns/hop | 同一数组、只把链打乱，慢 **37×** |
| `exp3` 工作集扫描 | 0.98 → 3.50 ns/hop（0→256 MiB），65 → 18 GB/s | 线性访问即使超出缓存，衰减也只有 3.5× |
| `exp4` 行/列优先 | 1.22 vs 12.91 ns/次（**10.6×**） | 另：缺页约 **1.34 µs/次**（351.49 ms / 262144） |
| `exp6` 伪共享 | 同线 1.07 vs 隔开 0.48 ns/次（**2.21×**） | 两核各加各的计数器 |
| `exp7` 换布局再测 | 紧循环 1.72 vs 0.71（差值 1.01 ns）；稀疏 7.34 vs 4.76（差值 2.58 ns） | 本机只有 2 个 vCPU，只能用 0/1 配对 |
| `exp5` 大页 | 仅得到 4 KiB 模式：8→256 MiB 为 13.7→140.7 ns/hop | **本环境 `AnonHugePages: 0 kB`，大页不可用**，2 MiB 对照组缺失 |

## 两条跨平台对照

拿本机数据和 ARM64（Snapdragon 8cx Gen 3）那份笔记比，有两点值得记住：

1. **伪共享的单位代价随机器变**：本机跨核差值约 1 ns/次（紧循环），笔记里 ARM 上约 2 ns/次。
   方向一致、量级差一倍——说明这类数字只能同机比较，不能跨机套用。
2. **线性 vs 随机差 37 倍**（3.96 vs 145），和笔记里「顺序与随机差四十到五十倍」同量级。
   **比例稳定、绝对值不稳定**，这正是可以写进结论的那种东西。

## 已知缺口

- `exp5` 缺大页对照组：需要在有 `HugePages_Total > 0` 的机器上重跑。
- `win_chase` / `win_share` 是 Windows 专用，未在本环境编译。
- 单核数据在 2 vCPU 虚拟机上采集，多核部分的绝对值受限于核数，`exp7` 只测了一对核。
