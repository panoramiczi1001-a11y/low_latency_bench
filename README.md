# Low-Latency Bench

把《新手如何步入 Quant Developer》里**能落到代码的知识点**，逐个写成可运行的实验，
并用统一口径测量。目标不是收集实验，是让不同实验之间的数字**可比**。

## 三条口径（所有实验都必须遵守）

1. **同时报告计时器开销。** `clock_getres` 报的分辨率和「读一次时钟要多久」是两件事，
   后者决定结果的可信上限。库见 `common/timer.h`。
2. **报分位数，不只报平均。** p50 / p99 / p999 —— 低延迟关心的是尾部。
3. **每个实验必须能回答四个问题**：假设是什么、怎么测的、结果是什么、这个结果的
   可信度受什么限制。

## 结构

```
common/timer.h        统一的计时与统计（各实验共用，不要各写一份）
ch03/                 对应书里第 3 章
  3_1_cache/          缓存层次、空间局部性、伪共享
  3_2_vm_alloc/       虚拟内存、缺页、大页
  3_x_container/      STL 容器的扩容与分配开销
results/              各实验的原始输出（入库，便于对比）
```

## 怎么跑

```bash
make                # 构建全部实验
make clean
cd ch03/3_x_container && make run N=100 ROUNDS=5000 REP=100
```

单核测量建议用 `taskset -c 0` 绑核，避免线程迁移干扰。

## 新增一个实验

1. 建目录 `ch03/3_x_<主题>/`，放入 `.cpp`
2. 计时与统计**直接 include `common/timer.h`**，不要复制粘贴
3. 写该目录的 `README.md`：目的 / 假设 / 方法 / 结果 / 限制
4. 把输出存进 `results/`，回到上面索引表加一行

## 环境说明

本仓库的数字来自**虚拟机与容器**，不代表裸机性能。跨平台对比时请连同
`clock_getres` 与计时开销一起报告——同一个程序在两台机器上，测量成本本身可能差十倍。
